# Грабли IPC-2581 и опыт проекта

Собрано из работы над лазерным тестером (совмещение снимка камеры с гербером, резка меди по геометрии платы).
Контекст: плата 160×160 мм, Altium → IPC-2581 rev B, 2190 отверстий, 107 компонентов.

## Разбор

* **Datum.** Координаты файла абсолютные (у нас ≈ 1270 ± 80 мм). Вычитайте `Step/Datum` один раз, на границе
  «разбор → модель», и дальше везде работайте «мм от Datum, вид сверху». Смесь систем — самый частый источник
  «всё уехало на 1270 мм».
* **Единицы.** Проверять `CadHeader@units` сразу. Не `MILLIMETER` — отказывать явно, а не молча масштабировать.
* **`clockwise="false"` — против часовой.** Ошибка знака превращает выпуклый угол контура в вогнутый. Проверять
  на контуре платы со скруглёнными углами: `ipc2581_svg.py` рисует дуги настоящими SVG-дугами — угол должен быть
  выпуклым.
* **`UserSpecial`.** Линии шелкографии и документных слоёв лежат внутри `Features/UserSpecial`, иногда глубже;
  разбор только прямых детей `Features` теряет почти все линии (у нас 48 581 из ~48 600 лежат в UserSpecial). Обходите рекурсивно.
* **Дубли отверстий.** Одно и то же отверстие есть в `PadStack/LayerHole` и в `LayerFeature/Set/Hole`.
  Дедупликация по (x, y, ⌀) с округлением до 1e-4, первое вхождение побеждает (оно из PadStack и несёт владельца
  через `PinRef`).
* **Округление.** Python-эталон округляет координаты отверстий до 1e-4 (`0.499999 → 0.5`) — только в ключе
  дедупликации; храните точные. При сверке двух читателей сравнивайте после одинакового округления.
* **Площадки со сложной формой** — `EntryStandard/Contour` (750 из 767 записей нашего словаря). Координаты контура
  формы — **локальные** (не вычитать Datum), поворот `Xform@rotation` у `LayerPad`.
* **Полигоны с вырезами.** `Contour/Polygon` + `Cutout*`; для «точка внутри» — чётно-нечётное правило на всех кольцах
  сразу. Дуги в кольцах (`PolyStepCurve`) перед point-in-polygon разворачивать в ломаную (`Tessellation.Ring`).
* **Молчаливые потери.** Негативные слои, `Xform` со сдвигом/масштабом, `Polyline`, `Text`, `UserPrimitiveRef`,
  `LineDescRef` — не разбираются. Хороший читатель не молчит, а копит предупреждения; `ipc2581.py` пока молчит. Если цифры
  не сходятся с CAD — сначала `ipc2581_inspect.py tags` и поиск таких элементов.
* **Несколько `Step`** (панелизация) — берётся первый; при >1 выводить предупреждение.
* **Скорость.** XML 15 МБ парсится ~0.5 с в C# (`XDocument`) и несколько секунд в ElementTree. Кэшируйте разбор,
  пока файл не менялся (время записи + размер) — в приложении так сделано, а не «парсить при каждом действии».

## Смысл данных

* **Материалы и толщины в стеке не равны реальным.** Медь 0.035 мм — умолчание Altium, фактическая — 70 мкм.
  Маска — `SOLDERMASK`-слой содержит **вскрытия** (где маски нет), а не саму маску; цвет маски нигде не хранится.
* **Высота компонентов** (`Component@height`, `standoff`) — из 3D-модели/библиотеки; годится для отбора высоких
  деталей. SMT-стойки M3×3 в нашем файле — обычные компоненты (`SMTSO3030MTJ (M3x3)`, M1…M8), сидящие **в
  отверстиях ⌀4.2** — отверстие ⌀4.2 с владельцем-стойкой не равно «свободному крепёжному».
* **Кто владеет отверстием** — через `PinRef` площадки того же `PadStack`: переходные (VIA) владельца не имеют, крепёж
  и разъёмы — имеют. На этом строятся правила «исключить из совмещения отверстия стоек/гаек» (по refdes, по имени
  посадочного места, по координате с допуском).
* **Какая сторона «верх».** Файл хранит обе стороны «сверху насквозь». Какая лежит вверх на станке — **не в файле**,
  это решение пользователя/проекта (`sideUp`: top/bottom) + поворот вида (`rotationHint`, кратный 90°). Для
  `bottom` вид «как видит камера» = зеркало по X. Перепутали сторону — совмещение «не находит плату»;
  автоматическая проверка стороны (перебор 4 зеркальных вариантов) оказалась нужна.
* **Цепи** (`Set@net`) — метки вида `NetPC Red-Orange 7_1`, `No Net`; полезны, чтобы выбрать «дорожку нужной цепи»
  для резки, и чтобы понять, какой полигон общий (связанные через него блоки греются вместе).

## Использование геометрии в реальном мире

* **Параллакс высоких деталей.** Камера, смотрящая косо, сдвигает верхушки стоек/разъёмов на 12–30 px; клики или
  привязка по ним ошибаются на 1–5 мм. Поэтому из файла берут высоту деталей и исключают «высокие» из точек привязки
  (корпус + запас «высота × 1»).
* **Мелкие переходные отверстия (⌀0.5, 2180 шт.)** — отличная опорная сетка для совмещения с фото: их много, они
  равномерны, не зависят от цвета маски; кольца вокруг видны по меди.
* **Шелкография** (слой LEGEND стороны) — источник точек вдоль геометрии (`SamplePoints(step)`), но на белой маске
  контраст другой: проверяйте, какой рисунок реально виден на снимке.
* **Точность.** Гербер точен до долей микрона; реальная плата отличается от него (травление, усадка, позиция). Для
  миллиметров на станке совмещайте по снимку/реперам, а не «по файлу».

## Сверка читателей (как делали)

1. Эталон — `dump_ipc_golden.py` (строит JSON из `ipc2581.py`): Datum, слои, контур по элементам, все отверстия,
   SIGNAL/LEGEND слои по элементам (6 407), у прочих слоёв — счётчики и суммы координат, компоненты — независимым
   ElementTree-разбором.
2. Новый читатель сверяется поэлементно до 1e-6 мм. Проверка чувствительности: сдвинуть одну линию на 2·10⁻⁶ мм —
   сверка должна упасть.
3. JSON эталона ~1 МБ: в репозиторий проекта кладут, но в этот skill — нет (снимается за секунды на вашем файле).

## Посадочные места (опыт аудита StandaloneTrackingSocket)
* **`Package/Pin` → StandardPrimitiveRef — это форма вскрытия маски, а не медь** (у Altium она больше на +0.05 мм с каждой стороны). Медь площадки брать из `PadStack/LayerPad` установленного компонента на слое его стороны и переводить в координаты корпуса: вычесть `Component/Location`, повернуть на −rotation, для нижней стороны отразить X. Готово в `tools/footprint.py`.
* Сравнивая с рекомендованной площадкой даташита, учитывать поворот (у библиотечного футпринта своя ориентация). Зеркальное отражение — ошибка.
* Некоторые формы в словаре (`Oval`) текущий `_primitives` не разбирает: площадка пропадает молча (у нас — вывод 1 светодиода).
